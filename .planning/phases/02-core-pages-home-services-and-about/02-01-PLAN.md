  <action>
Create `src/components/motion/MagneticButton.tsx` following 02-RESEARCH.md Pattern 2:
- Props: `children: ReactNode`, `strength?: number` (default `0.3`).
- Wraps children in a `<div ref={ref} className="inline-block">` so it can wrap a `Button` or link without altering its own styling.
- `useGSAP(() => {...}, { scope: ref })`.
- `gsap.matchMedia()` with conditions `reduceMotion: "(prefers-reduced-motion: reduce)"` and `isFinePointer: "(pointer: fine)"`.
- If `reduceMotion || !isFinePointer`, return early with **no event listeners attached at all** (button stays a normal static, fully clickable element — this is the touch/mobile degrade path for ENG-05).
- Otherwise: create `xTo`/`yTo` once via `gsap.quickTo(el, "x" | "y", { duration: 0.4, ease: "elastic.out(1, 0.3)" })` (never recreate a tween inside the mousemove handler — this is the #1 documented perf mistake per research).
- `mousemove` computes offset from element center * `strength`, calls `xTo`/`yTo`; `mouseleave` calls `xTo(0)`/`yTo(0)`.
- Cleanup removes both listeners; outer `useGSAP` cleanup calls `mm.revert()`.
- Stays content-agnostic — no domain-specific props, works with any children (a `Button`, an anchor, etc.).
  </action>
